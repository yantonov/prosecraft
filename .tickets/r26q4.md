# Harness trait: a session id may come from the harness's own event stream

## Problem

The trait assumes every harness is *told* its session id. `HarnessAdapter::new_session_id`
mints one, `build` puts it in the argv, and `Machine` reads it back out of the argv with
`session_from` (`src/rewrite.rs`). Measured, codex breaks all three links: it names its own
thread, ignores a client-supplied `-c thread_id=`, and reports the id on stdout as

    {"type":"thread.started","thread_id":"01a1bc23-1144-7de2-9a09-7a777c4a420c"}

so the id exists only in the event stream, after the process has started.

This ticket makes the contract express both kinds of harness, and nothing else. It is
deliberately before the codex adapter so that adapter can be a table of argv and a table of
event lines, with no session plumbing inside it.

## Design

Two trait changes and one machine change:

- `fn new_session_id(&self) -> Option<String>` — `Some` for a harness the client names
  (claude, pi), `None` for one that names itself (codex). `None` is not "no session": it
  means "ask the stream".
- `fn session_from_event(&self, line: &str) -> Option<String>` — the terminal-free
  counterpart, defaulting to `None`. claude and pi keep the default; codex parses
  `thread.started`.
- `Machine` keeps learning the id from the argv first (unchanged for claude and pi) and
  falls back to `session_from_event` on each stdout line it drains, only while it has no id.
  `Machine::tick` already holds the lines and the adapter, so this adds no new plumbing.

`Ctrl+N` must still work: after a reset the next run must open a *new* codex thread, which
it does, because an unnamed first call starts a fresh thread and the new id is learned from
the new stream.

## Done when

- `HarnessAdapter::new_session_id` returns `Option<String>`; claude and pi return `Some`,
  and their existing id-shape tests still assert on `Some`.
- `session_from_event` exists with a `None` default, so a third-party adapter need not
  implement it.
- `Machine` learns the id from the argv when the adapter supplies one, and from the event
  stream otherwise. A test drives a fake adapter that names no session and emits the id on
  stdout, and asserts `machine.session()` becomes that id and stays it across a second run.
- A test asserts a run after `Ctrl+N` adopts the *second* stream's id, not the first.
- Both existing adapters are unchanged in behaviour: their argv tables pass untouched.
- `make check` green.
